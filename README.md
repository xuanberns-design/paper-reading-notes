# 论文精读笔记与复现

> 一周精读一篇。每篇留下两样东西：一页自己的见解，和能跑通的复现。
> 不求全，只求真——复现到哪一步，就写到哪一步。

## 目录（每篇一个文件夹）

- `papers/01-kaist-multispectral/` — KAIST 多光谱行人检测基准（CVPR 2015）：数据集论文，先搞懂双模态检测的“地形”
- `papers/02-yolov1/` — YOLOv1（CVPR 2016）：YOLO 家族的起点

后续按精读顺序往下排：03、04……

## 每篇的文件夹长这样

```
papers/01-kaist-multispectral/
├── note.md          # 见解：一页笔记（骨架见下）
└── repro/
    ├── README.md    # 复现说明（模板见下）
    └── ...          # 自己跑通的代码
```

没有能力复现的部分就不建 `repro/`，在 note.md 里写清为什么跳过，不硬凑。

## note.md 骨架（照着填，必须用自己的话）

- 出处：标题 / 作者 / 会议或期刊 / 年份 / 链接
- 问题：一句话，这篇论文要解决什么
- 方法：它怎么做的（能画图就画一张）
- 实验：在什么数据上、效果如何
- 局限与批判：今天看哪里过时了、哪里站不住
- 对我有用吗：对应我微气象机器人三层架构的哪一层？一期大创能不能用？差在哪
- 我的见解：与作者结论不一致、或我想追问的地方（和上面分开写，标清哪些是作者的、哪些是我的）

## repro/README.md 模板（复现说明，诚信线在这里）

- 复现了原文的哪一部分：（例如“只跑通了数据集加载和样本可视化，没跑 baseline 训练”）
- 环境：系统 / 框架版本 / 硬件
- 怎么跑：一条能直接复制的命令
- 我的结果 vs 原文结果：数值对照，差多少、可能为什么
- 没复现的部分：是什么、为什么没做（没数据 / 没算力 / 还没学到），不装懂

## 三条底线

1. 见解必须是自己的话；作者的观点和我的批判分开标，不混。
2. 复现只放自己真跑通的；跑不通就写清卡在哪一步，那也是记录。
3. 每篇必须注明出处，引用数字要能指回原文的表和图。
